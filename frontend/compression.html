先建立心智模型：到底在压缩什么

四个问题决定后面所有选择
Q1 / OBJECT

压缩对象

权重 W、激活 A、KV Cache、梯度/优化器状态、输入 token 数、去噪步数、网络层数。剪枝偏「删结构」，量化偏「降精度」。

Q2 / WHEN

压缩时机

PTQ（训练后，小时级，无需训练数据标签）、QAT（训练中感知量化）、蒸馏（教师带学生）、结构化剪枝后必须做恢复训练。

Q3 / GAIN

收益来源

显存 = 参数量 × 位宽 ÷ 8；带宽与缓存决定 decode 吞吐；算力决定 prefill / 扩散去噪。压缩不一定等于加速，取决于内核是否支持。

Q4 / COST

代价

精度、泛化、长尾任务、时序一致性、硬件门槛。压缩后必须用同一套评测集做 A/B，不能只看文件变小。

显存账本：真实算术（拖动滑块，实时计算）

公式：权重 = P × bit / 8 / 1024³；KV = 2 × 层数 × 序列数 × token 数 × KV头数 × 头维 × bit / 8 / 1024³（2 = K 与 V）。实际部署还要加激活、CUDA context、临时 buffer，通常再留 10%–25% 余量。

1.2 通用七步操作流程（所有模态都适用）

01

建立基线与预算（不要跳过）

固定随机种子、固定评测集、固定 prompt 模板，记录：PPL / 任务准确率 / FID / FVD / ULIP，以及显存峰值、首 token 延迟、吞吐。同时写下硬约束，例如「至少 50% 稀疏」「显存 ≤ 24 GB」「PPL 上升 ≤ 0.5」。

产物 → baseline.json（可复现的实验基线）
02

依赖图发现（Discovery）：找出最小可移除单元 group

Transformer 里一个维度常被多条路径共用：残差相加要求分支宽度一致；RMSNorm / LayerNorm 的参数与隐藏维绑定；GQA 下一个 KV 头被多个 query 头共用；FFN 的 up/gate/down 三矩阵在中间维耦合。DepGraph 把耦合的层与维度合并成一个 group，剪枝时整组一起删，否则会破坏张量相加/拼接的形状一致性。

结构化剪枝工具（LLM-Pruner）会先跑这一步；非结构化剪枝可以跳过。

产物 → 依赖图 / group 列表（记录每个 group 覆盖的层与轴）
03

重要性估计（Estimation）：给每个 group / 权重打分

常见四种评分：

  • Magnitude：sij = |Wij|，零成本但忽略激活尺度。
  • Wanda：sij = |Wij| · ‖Xj‖₂，按输出行做 per-output 比较，需要 128 条左右校准样本，无反向传播。
  • Taylor / 一阶梯度：I(g) ≈ |∂L/∂Wg · Wg|，LLM-Pruner 默认 param_mix 会混合一阶与二阶近似，需要反向，显存开销更大。
  • 二阶 / Hessian（SparseGPT、OBS）：用 H = XXᵀ 的逆更新剩余权重以补偿误差，精度最高，成本也最高。
产物 → importance score（每权重的标量或每 group 的分数）
04

生成掩码并施加

非结构化：M = 1[s > threshold]，W ← W ⊙ M；2:4：在每 4 个连续权重内保留分数最高的 2 个；结构化：按 group 分数排序后删除整组索引，用 torch.index_select / 切片重建权重张量，并同步修改 config.json（hidden_size、intermediate_size、num_attention_heads、num_key_value_heads、num_hidden_layers）。

产物 → 掩码 / 新权重 / 新 config
05

结构重建与导出

注意绑定权重（tied embedding 与 lm_head 必须同步）；GQA 下 query 头数与 KV 头数比例必须保持整数；每层宽度可能不同，LLM-Pruner 官方因此使用 torch.save 而不是 HF from_pretrained 加载。导出时验证 safetensors 中每个张量的形状与 config 一致。

产物 → 可加载的剪枝 checkpoint
06

恢复训练（Recovery）

结构化剪枝会实质性损害模型，必须做 post-training。LLM-Pruner 官方用 5 万条 Alpaca 样本、LoRA r=8、2 epoch、lr 1e-4；大规模语料版本用 259 万条 LaMini-instruction、3 epoch、lr 5e-5。剪枝强度越大，恢复数据越多。注意 Llama-2 训练用 bf16（fp16 容易出 NaN）。

产物 → 恢复后的模型 + LoRA 权重（可 merge）
07

验收与部署

先测 PPL 与任务精度，再测 MACs / 参数量 / 显存，最后测真实引擎吞吐。若用 2:4，确认推理后端启用了稀疏内核；若为非结构化，先确认是否有稀疏 kernel，否则实测往往「参数少了、速度没变」。最后做长上下文与长尾任务回归。

产物 → 验收报告（精度 + 速度 + 显存三项）

1.3 五种代表算法：公式、代价与适用边界

MAGNITUDE

幅值剪枝：一切的地基

把权重绝对值最小的置 0。优点：无数据、无梯度、可解释；缺点：忽略输入通道尺度，高稀疏度下精度掉得快。通常作为 baseline 而不是最终方案。Wanda 论文中 LLaMA-7B 50% 非结构化稀疏的 PPL：magnitude 8.45，Wanda 6.18，SparseGPT 6.32（FP16 基线 5.68）。

WANDA · ICLR 2024

权重 × 激活范数

sij = |Wij| · ‖Xj‖₂。按每个输出行独立比较，保证每个输出神经元保留相似容量。只需约 128 条 × 2048 token 的校准文本，不做权重更新、不需要反向传播；支持 unstructured / 2:4 / 4:8。适合「一小时出结果」的 one-shot 场景。

Wanda 官方命令
python main.py \
  --model decapoda-research/llama-7b-hf \
  --prune_method wanda \
  --sparsity_ratio 0.5 \
  --sparsity_type unstructured \
  --save out/llama_7b/unstructured/wanda/

# 硬件友好的 2:4 半结构化
python main.py --model ... --prune_method wanda \
  --sparsity_ratio 0.5 --sparsity_type 2:4 \
  --save out/llama_7b/2-4/wanda/
SPARSEGPT · ICML 2023

Hessian 补偿的 one-shot 稀疏

逐层用校准激活构造 H = XXᵀ，按列选择要剪的权重，并把被剪列造成的误差用 OBS 更新分摊到剩余权重：W ← W − e·uᵀ / H⁻¹jj。因此 50% 稀疏几乎不掉点。支持非结构化、2:4、以及「稀疏 + 4bit」联合压缩。代价是 H 的求逆与更新开销。

SparseGPT 官方命令
python opt.py facebook/opt-125m c4 --sparsity .5   # 50% 非结构化
python opt.py facebook/opt-125m c4 --prunen 2 --prunem 4 # 2:4
python opt.py facebook/opt-125m c4 --sparsity .5 --wbits 4 # 稀疏 + 量化
python llama.py LLAMA_HF_WEIGHTS_LOCATION c4 --sparsity 0.5
LLM-PRUNER · NEURIPS 2023

靠依赖图做真正的结构压缩

三阶段：Discovery（找 group）→ Estimation（Taylor 打分）→ Recover（LoRA 恢复）。支持 block-wise / channel-wise / layer-wise 三种策略，支持 Llama-3.1 / Llama-3 / Llama-2 / BLOOM / Vicuna / Baichuan / TinyLlama，并已支持 GQA。官方例子：Llama-7B 剪掉约 20% 参数后恢复训练，可接近原始模型能力。

LLM-Pruner 官方命令
# ① 剪枝：Taylor 估计 + 块级剪枝
python hf_prune.py --pruning_ratio 0.25 --block_wise \
  --block_mlp_layer_start 4 --block_mlp_layer_end 30 \
  --block_attention_layer_start 4 --block_attention_layer_end 30 \
  --pruner_type taylor --device cpu --eval_device cuda \
  --save_ckpt_log_name llama_prune

② 恢复：Alpaca 5 万条 + LoRA
python post_training.py --prune_model prune_log/.../pytorch_model.bin \
  --data_path yahma/alpaca-cleaned --lora_r 8 \
  --num_epochs 2 --learning_rate 1e-4 --batch_size 64
DEPGROUP · CVPR 2023

跨架构的通用依赖建模

把网络解析成图，自动识别耦合组，让同一套剪枝器能用于 Transformer、CNN、检测器等不同结构。LLM-Pruner 的 group 发现就建立在 DepGraph 思路上。适合你想把剪枝迁移到自定义多模态模型（ViT + 投影层 + LLM）时使用。

TOKEN / ATTENTION 剪枝

不改权重，改「进入模型的序列」

VLM 中大量视觉 token 是冗余的：FastV 依据注意力在后层丢弃 patch token，VisionZip 在前者聚合相似 token，AngelSlim 提供通用 metadata-driven 视觉 token pruning/merging 框架。LLM 长上下文侧，MInference 用 A-shape / Tri-shape 等稀疏模式加速 prefill。结构变化是 [T,d] → [k,d] 或注意力掩码变化，权重完全不动。

剪枝最常见的三个坑：① 把「非结构化稀疏率」当成「加速倍数」——没有稀疏内核时速度几乎不变；② 结构化剪枝后忘记同步 config / 绑定权重 / GQA 头数比例，加载即报错；③ 剪完不做恢复训练就上评测，得到「剪枝不可用」的错误结论。
02

量化：从浮点到整数的每一步

Quantization · 精度换显存与带宽

2.1 数学基础：一个公式解释所有 INT 量化

Q(r) = clamp( round(r / s) + z, qmin, qmax )　·　r̂ = s · ( Q(r) − z )　// s=scale（步长）, z=zero-point（零点）

若 z = 0 且量化区间关于 0 对称，称为对称量化（LLM 权重常用）；否则是非对称/仿射量化（激活常用，因为 ReLU 后分布不关于 0 对称）。量化粒度从粗到细：per-tensor → per-channel → per-group（典型 g128）→ per-block / per-token。粒度越细精度越好，scale/zero-point 的额外存储越多。

FLOAT FORMATS

FP8 / FP4

e4m3fn：4 位指数 + 3 位尾数，动态范围小但精度较好，是 Hopper/FLUX 常用格式；e5m2：范围大、尾数少。NVFP4 / MXFP4 是 4 位浮点，需要 Blackwell 等新硬件。浮点量化通常不需要 zero-point。

INTEGER FORMATS

INT8 / INT4 / NF4

INT8 用 256 个均匀台阶；INT4 只有 16 个台阶，必须配 per-group scale。NF4（QLoRA 使用）是按正态分布设计的 4 位非均匀格式，对权重分布更友好。GGUF 的 Q4_K_M 是 K-quant 分组 + 混合精度方案。

NOTATION

WxAy 记法

W4A16 = 4-bit 权重、16-bit 激活（weight-only，省显存为主）；W8A8 = 权重和激活都 8-bit（省显存 + 算力）；W4A8 是折中。KV Cache 位宽单独标记，常见 KV8 / KV4。

2.3 PTQ 八步标准流程（训练后量化）

01

按硬件选方案，而不是按比特数选

Hopper（H100/H200）优先 FP8 W8A8；Ampere/Ada（A100/4090）优先 INT4 W4A16（AWQ / GPTQ），也可走 Marlin 内核；CPU / llama.cpp 走 GGUF Q4_K_M；Blackwell 可用 NVFP4。先查部署框架支持矩阵（例如 vLLM 官方文档列出 AWQ/GPTQ/FP8/INT8/GGUF 在不同算力上的支持情况）。

产物 → 量化方案 + 目标内核
02

准备校准集

128–512 条样本即可（AWQ / Wanda 论文用 128 条），长度 2048 token 左右，必须与真实业务分布接近（中文场景用中文语料，代码场景用代码）。不需要标签。校准集只用于统计激活范围/重要性，不用于训练权重。

产物 → calib.jsonl
03

插入 Observer 统计分布

对每个待量化线性层挂 hook，记录输入 X 与权重 W 的 min/max、直方图或 MSE/KL 最优阈值。这一步得到的 scale/zero-point 决定后续所有量化误差。按 per-channel 或 per-group 记录比 per-tensor 精度显著更好。

产物 → scale / zero-point 表
04

处理离群值（决定 INT4 成败的关键）

  • SmoothQuant：把激活上的离群值「搬」到权重上——W′ = W·diag(s)，X′ = diag(s)⁻¹X，其中 sj = max|Xj|α / max|Wij|1−α，典型 α≈0.5。之后 W8A8 才做得准。
  • AWQ：识别约 1% 的显著权重通道，用逐通道缩放保护它们：mins ‖ Q(W·s)·(s⁻¹X) − WX ‖²。只做缩放搜索，不做反向传播，泛化好。
  • GPTQ：用 Hessian 重构最小化层输出误差，配合 act-order（按激活重要性排序量化列）与 true-sequential（块内顺序量化）。Llama-7B Wiki2 PPL 从 RTN 4bit 的 6.29 降到 6.09；act-order 让 7B 从 7.15 降到 6.09。
产物 → 保护后的量化参数 / 缩放因子
05

执行量化与打包

把浮点权重映射成 int4/int8 并打包（例如两个 int4 塞进一个 byte），写入 safetensors / GGUF，同时保存量化配置 quantization_config（bits、group_size、scheme、sym、ignore 列表）。通常把 LayerNorm / RMSNorm、embedding、lm_head、router 保留高精度。

产物 → 量化 checkpoint
06

先 fake quant 评估，再 real quant 评估

AWQ 官方流程明确分两步：--q_backend fake 做模拟量化快速筛参，--q_backend real 生成真实权重。 Fake 与 real 的 PPL 若差距明显，说明 kernel / 打包路径有问题。

产物 → 精度对比表
07

部署并锁定内核

启动服务时显式指定量化方式与内核。vLLM 会在硬件不支持请求的激活量化时自动回退到 weight-only（W8A8 → W8A16），这不掉精度但也不再是你校准过的方案；严格模式设 VLLM_STRICT_QUANT_SCHEME=1 可禁止静默回退。

产物 → 实际运行的服务 + 日志
08

回归、监控、准备回滚

对比 PPL / MMLU / GSM8K / 业务集，以及 TTFT、TPOT、并发上限。保留原始 BF16 checkpoint 与完整配置，一旦长尾任务劣化立刻回滚或对该层提高位宽（混合精度逐张量分配）。

产物 → 上线报告 + 回滚点

2.5 QAT：什么时候 PTQ 不够

WHEN QAT

触发条件

目标 < 4 bit；激活也要量化到 4–8 bit；领域非常窄但对精度敏感；PTQ 后长尾任务掉点超过阈值。QAT 用直通估计器（STE）把量化不可导的 round 近似掉，在训练中让权重适应量化噪声，通常 1–3 个低学习率 epoch 即可。

HOW

最小可行流程

伪代码 · QAT 训练循环
for layer in model.layers:
    layer.q = FakeQuant(bits=8, scheme='per_channel')

更实用的是用 AngelSlim 的量化蒸馏配置：先得到 PTQ 模型，再以全精度模型为教师做 scale-only / 权重蒸馏，导出适配 vLLM / SGLang 的 checkpoint。

量化最重要的经验法则：不要整体降位宽。遇到精度瓶颈时先做逐张量敏感性分析——归一化层、router、output head、数值敏感的门控保留 BF16/FP8，参数冗余大的 QKV / FFN 上下投影压到 4bit。这个「敏感度优先、预算硬约束」的分配方式，比统一 4bit 更稳。

RULE 1

每次只改一个变量

把「剪枝率 + 量化位宽 + 步数蒸馏 + Cache」四个旋钮一次性拧到底，出了问题根本无法定位。正确做法是逐级叠加、逐级评测，每一级保留 checkpoint。

RULE 2

精度预算要分层分配

先做敏感性分析：逐层单独降 bit 看 PPL 变化。敏感层保留 8/16bit，冗余层降到 4bit。这比全模型统一降位宽更划算。

RULE 3

评测集必须覆盖长尾

「平均 PPL 没变」不代表业务没坏：中文、代码、数学、长上下文、多轮指令、结构化输出都要测。生成模型还要测运动一致性、材质正确性等专用指标。

什么时候跳过剪枝？如果你只是想让 70B 模型在 24GB 卡上跑起来，直接 AWQ W4A16 就够了，结构化剪枝需要恢复训练、重新评测，投入产出比低。剪枝更适合：显存/算力预算极紧、需要真实缩小架构、模型本身存在明显冗余（如多模态中大量视觉 token）。

6.1 Wan2.2 为什么是当前开源最佳实践的载体

ARCHITECTURE

MoE 双专家

总参数约 27B，每步只激活约 14B：高噪声专家（t > tmoe）负责布局，低噪声专家负责细节，切换点由 SNR 决定。计算成本接近 14B 模型，容量接近 27B。

ECOSYSTEM

加速栈最完整

官方支持 FSDP + DeepSpeed Ulysses（--ulysses_size 8）；社区有 DiffSynth-Studio（FP8、逐层卸载、序列并行）、LightX2V（4 步蒸馏 + 量化 + 轻量 VAE）、FastVideo（稀疏注意力）、Cache-dit（DBCache / TaylorSeer / Cache CFG）。

LICENSE

可商用

Apache-2.0，ComfyUI 原生节点与 diffusers 一线支持，适合生产落地；同级的 HunyuanVideo（13B）与 LTX-Video（2B/22B）也是可选路线。

02

先做步数蒸馏：50 步 → 4–10 步

这是视频侧收益最大的一步。LightX2V 提供 Wan2.1/2.2 的 4 步可用蒸馏模型与 LoRA；FastVideo / FastWan 用 consistency + 分布匹配把 50 步压到 5–10 步。结构变化：网络权重形状不变，变的是去噪循环次数与调度器；蒸馏 LoRA 可合并进主干。

03

量化：先 A/B，再上线

社区常用 fp8_e4m3fn（4 位指数 + 3 位尾数），由 DiffSynth-Studio / LightX2V / ComfyUI WanVideoWrapper 提供。但必须做实测：有社区实验在 Wan2.2 与 LTX 上发现，同体积下 Q8_0 的画面漂移约为 FP8 的一半，FP8 甚至出现「红色汽车倒着开」的运动语义错误；Q4 后人物身份漂移，Q3/Q2 运动物体崩坏。这是提示词与模型相关的经验，不是普适定律——结论是：固定 seed、固定提示词，至少测 3 类运动场景再定量化的默认档。

量化边界：DiT 双专家权重可量化，tmoe 切换逻辑、时间步嵌入、VAE、T5 文本编码器保持 BF16/FP16。专家的 scale 必须分别统计，否则切换点附近的画质会跳变。
04

缓存：跳过相邻去噪步的重复计算

TeaCache 在 Wan / HunyuanVideo 上常见 1.8–2.5× 加速、FBCache 更激进可达 2–3×；Cache-dit 提供 DBCache / TaylorSeer / Cache CFG，针对 Wan2.2 的 MoE 双专家切换做了专门处理。可与步数蒸馏叠加：蒸馏把 50 步变 8 步，Cache 再跳过其中约一半的块计算，合并加速可达 5–10×。

05

注意力与并行

视频 token 数 = 帧数 × H/patch × W/patch，注意力是 O(N²)。SageAttention 用低精度注意力替换 softmax 中的 matmul；VSA / FastVideo 用稀疏注意力只算重要块；多卡用 Ulysses 序列并行切分序列维。VAE 侧用 tiling / slicing 与帧分块解码避免峰值 OOM。

最佳实践 ④：文生 3D 模型

代表：Hunyuan3D 2.1（Shape 3.3B DiT + Paint 2B PBR）

3D 生成的压缩有两层含义：模型侧（Shape DiT / Paint 网络的量化与缓存）和产物侧（mesh 减面、纹理图集与 PBR 贴图压缩）。产物的结构压缩往往比模型权重压缩更能决定能不能塞进游戏引擎。

7.2 五步流水线

01

跑通两阶段基线

官方 diffusers-like API，先 Shape 得到 mesh，再 Paint 得到 PBR 贴图。固定输入图与 seed，保存中间 mesh（这一步同时也是显存分阶段的关键）。

Hunyuan3D 2.1 官方代码骨架
from textureGenPipeline import Hunyuan3DPaintPipeline, Hunyuan3DPaintConfig
from hy3dshape.pipelines import Hunyuan3DDiTFlowMatchingPipeline

shape_pipeline = Hunyuan3DDiTFlowMatchingPipeline.from_pretrained(
    'tencent/Hunyuan3D-2.1')
mesh_untextured = shape_pipeline(image='assets/demo.png')[0]

paint_pipeline = Hunyuan3DPaintPipeline(
    Hunyuan3DPaintConfig(max_num_view=6, resolution=512))
mesh_textured = paint_pipeline(mesh_path, image_path='assets/demo.png')
02

Shape DiT 做 FP8 权重量化

优先选官方/社区提供的 FP8 权重；或用 AngelSlim 的 diffusion FP8 流程对 DiT 做 per-tensor 量化。不要动几何解码（VAE / occupancy → Marching Cubes）与 Paint 阶段的精度，前者决定表面完整性，后者决定 PBR 材质正确性。

03

分阶段 + 低显存参数

把 Shape 生成的 mesh 落盘、释放显存，再启动 Paint。Gradio 可用 --low_vram_mode；ComfyUI 可加 --reserve-vram 1~2。控制 max_num_view=6、resolution=512，批量大小保持 1。

python3 gradio_app.py \

  --subfolder hunyuan3d-dit-v2-1 \
  --texgen_model_path tencent/Hunyuan3D-2.1 \
  --low_vram_mode
04

步数 / 缓存 / 视图裁剪

Shape 的 flow matching 步数可用缓存类方法（TeaCache / TaylorCache，AngelSlim 已覆盖 diffusion 类模型）减少重复计算；Paint 阶段减少多视图数量或分辨率是最直接的算力旋钮，但会牺牲纹理完整度——一般优先降到 4 视图而不是降到 256 分辨率。

05

产物侧结构压缩（3D 特有）

用 QEM（二次误差度量）减面：几十万面 → 几万面，并生成 LOD0/1/2；把多张 PBR 贴图打成图集，金属度/粗糙度合并到同一张图的不同通道；导出 glTF/GLB 时在 Unity / Unreal 中验证材质。注意：这一步不改变模型权重，但决定资产能否实时渲染。

其他优化手段：剪枝与量化之外的工具箱

12 种手段 · 原理 / 结构变化 / 何时用 / 风险
01 · DISTILLATION

知识蒸馏

原理：教师 softmax / logits / 中间特征监督学生，L = α·KL(pT‖pS) + (1−α)·CE(y,pS)。结构变化：学生可以是更小的层数/宽度，也可以是同结构的量化模型。何时用：剪枝后恢复、低比特补偿、扩散模型的步数蒸馏（DMD2 / consistency）。风险：教师偏好的长尾行为会被继承，需保留原任务评测。

02 · SPECULATIVE DECODING

投机解码

原理：小模型一次猜 γ 个 token，大模型一次并行验证；接受概率 α = 1 − min(1, p/q)，拒绝时从修正分布重采样。结构变化：增加草稿头/草稿模型（EAGLE3、Medusa、MTP、DFly2），主模型权重不动。何时用：低并发、长输出、延迟敏感。风险：高温采样接受率下降；显存要多放一份草稿模型。

03 · KV CACHE

KV Cache 量化与分页

原理：把 K/V 从 16bit 降到 8/4bit；KIVI 对 key 按通道、value 按 token 量化以控制离群；PagedAttention 用分页管理避免碎片。结构变化：[L,2,T,Hkv,dh] 的元素位宽与内存布局变化。何时用：长上下文、高并发。风险：极长上下文下逐 token 误差累积，需 per-head 抽检。

04 · TOKEN PRUNING

Token / Patch 剪枝与合并

原理：依据注意力分数或相似度丢弃冗余视觉/文本 token。结构变化：[T,d] → [k,d]，注意力矩阵从 T² 降到 k²。何时用：VLM 高分辨率图像、视频多帧、长文档。代表：FastV、VisionZip、DivPrune、IDPruner。风险：小目标、细粒度文字最先被丢掉。

05 · SPARSE ATTENTION

稀疏注意力 / 长上下文模式

原理：只计算注意力矩阵中的部分块（A-shape、Tri-shape、滑动窗口 + 汇聚点）。结构变化：掩码模式变化，权重不变。何时用：32K–1M 上下文 prefill。代表：MInference、FlexPrefill、XAttention、FlashPrefill。风险：需要「大海捞针」评测，警惕中间位置丢失。

06 · FLASH ATTENTION

IO 感知的精确注意力

原理：分块计算、避免把 N×N 注意力矩阵写回 HBM，数学上精确无近似。结构变化：只换内核，模型和掩码语义不变。何时用：几乎所有 GPU 训练/推理的默认项。风险：版本与 GPU 架构绑定；小序列收益有限。

07 · LOW-RANK

低秩分解 / LoRA 合并

原理：用 ΔW = BA（r ≪ d）近似权重变化。结构变化：训练时多两条旁路，推理时可合并回 W′ = W + (α/r)BA，零额外延迟。何时用：微调、多任务热切换、压缩恢复训练。风险：秩太低拟合不了复杂任务。

08 · EARLY EXIT

提前退出 / 自适应计算

原理：在中间层挂分类器，简单样本提前输出。结构变化：增加若干轻量 head，主干不变；推理时跳过后续层。代表：SpecExit（官方称推理长度减少约 66%）。风险：退出阈值需要按任务校准，复杂推理题容易误退。

09 · STEP DISTILLATION

扩散步数蒸馏 / 一致性模型

原理：把多步去噪映射压缩到 1–8 步。结构变化：权重形状不变，去噪循环长度与调度器变化，常以 LoRA 形式交付。代表：FLUX schnell（4 步）、LightX2V / FastWan（视频）、LCM / Turbo。风险：细节与文字渲染下降，需重调 guidance。

10 · FEATURE CACHE

跨步特征缓存

原理：相邻去噪步的特征高度相似，缓存后跳过部分 block。结构变化：计算图按步动态跳过，权重完全不动。代表：TeaCache、DeepCache、FBCache、TaylorCache、DBCache。风险：快速运动镜头跳过过多会丢时序细节。

11 · PARALLELISM

并行策略与调度

原理：TP（张量维切分）、PP（层切分）、EP（MoE 专家切分）、CP/SP（序列切分）、连续批处理与 chunked prefill。结构变化：权重分片布局与通信拓扑变化，数学等价。何时用：大模型 / 长视频 / 高分辨率 3D。风险：通信开销可能吃掉加速收益。

12 · ASSET COMPRESSION

产物级压缩

原理：mesh 减面与 LOD、贴图图集与 ASTC/BCn 压缩、视频 H.264/H.265。结构变化：只改输出资产拓扑与编码，模型完全不动。何时用：游戏/AR/移动端交付。风险：不影响推理速度，但直接影响最终观感，需人工复核。

9.2 上线前最终检查清单

DO
  • 保留 BF16 原始 checkpoint 与各阶段中间产物
  • 量化配置随模型一起版本化（bits / scheme / group / ignore）
  • 固定 seed 与提示词做 A/B，报告差值而非绝对值
  • 先逐张量敏感性分析，再决定不同层的位宽
  • 用目标推理引擎实测，不信理论 FLOPs
  • 检查 vLLM 是否发生静默内核回退
DON'T
  • 不要把非结构化稀疏率当作加速倍数
  • 不要对 MoE 的 router / gate 做低比特量化
  • 不要量化 VAE / 时间步嵌入等高敏感小模块
  • 不要一次性叠加剪枝 + 4bit + 蒸馏 + Cache
  • 不要只看平均指标，忽略长尾与业务分布
  • 不要在未知内核支持的硬件上承诺加速
回滚策略：一旦发现质量退化，按逆序撤销：先关 Cache → 再恢复步数 → 再把量化升到 8bit → 最后才恢复剪枝前的结构。因为越靠后的改动越「便宜」，先撤它能最快定位问题。
